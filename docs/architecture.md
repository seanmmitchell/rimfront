# Native architecture (0.5.5)

RimFront now runs its view, input, and game integration in the RimWorld process. The active path has no browser, JSON snapshots, loopback listener, HTTP polling, or separate simulation.

```
Native keyboard/mouse -> NativeView -> RimFrontGame -> native movement/attack/reload jobs
                            |                              |
                   perspective camera             authoritative game state
                            |                              |
                            +--------- NativeScene <-------+
                                         |
                              engine mesh draw submissions
```

`NativeView` temporarily owns the existing map camera and input. It configures perspective projection, follows analog coordinates or authoritative native path progress at eye height, captures mouse motion, and provides a HUD including the active movement mode. Bounded frame interpolation bypasses the slower colony pawn-position spring. Harmony intercepts the normal camera/UI and flat map/dynamic rendering while possession is active. Saved camera/cursor/subcamera/background settings are restored on exit. Controlled-pawn hooks pass through when possession ends.

`NativeWindowIcon` protects the existing Windows game-window icons during entry and release. Capture precedes camera/cursor mutations; restoration runs even after transition cleanup errors, with checks limited to a short transition window rather than ongoing polling. Owned icon copies remain alive for the process lifetime so Windows never displays a destroyed handle. This is a defensive safeguard for a reported regression; the cause and live taskbar behavior remain unverified.

`RimFrontGame` grants possession only through a local pawn command, verifies eligibility, and consumes frame input on game ticks. It temporarily disables fire-at-will and restores it on release. Attack warmup, bursts, cooldown, and reloads remain native. Changing the save/map, blocking dialogs, focus loss, undrafting, downing, death, an external incompatible job, or other loss of eligibility releases control. Possession is not saved.

`NativeJobPolicy` distinguishes RimWorld's automatic one-tick posture wait from actual external orders. Only an unforced, nonsleeping `Wait_MaintainPosture` with expiry exactly one tick receives the transitional exemption. Longer, forced, sleeping, and unrelated jobs still release control; existing owned/wait/reload handling remains intact.

`AnalogMovement` owns the controlled pawn's continuous XZ position while active. `AnalogCollision` sweeps a square footprint against map blockers, slides at contact, and prevents tunneling. Native movement costs determine distance, capped at 0.25 cells per tick. Cell transitions use the normal position setter and notify filth, snow, doors, clamor, and movement bookkeeping. Native pather ticks and new paths are suppressed only for the owned pawn. Door closure waits until the continuous body clears the old doorway. The footprint includes the larger of visible and CE bounds; unsupported dimensions select native fallback. `RimFrontSettings` stores the analog preference. Native fallback uses look-ahead path orders, retaining the regular pather and collisions.

The 0.4.1 collision sweep reserves a world-space separation sized for float precision at the current map coordinates. This prevents double-precision contact results from rounding back inside a wall when saved as game floats. It repairs only rounding-scale overlaps; deeper new obstacles still block movement. Pawn occupancy uses the game's native traffic predicates instead of treating every friendly standing pawn's entire cell as solid.

`NativeAimTargeting` tests the view ray against displayed pawn bounds and scenery triangles, choosing the nearest target without a faction filter, or a visible empty endpoint. `CombatAdapter` checks the weapon and requests a native attack. `NativeManualAim` scopes mouse-driven aim updates to that exact pawn, verb and owned attack job; other pawns keep their native targeting. The scoped free-fire shoot-line check uses the selected geometry and native range; actual projectiles determine contacts. The game or CE retains spread, armor, injury, shields and ammunition. Optional CE reflection validates the public ammunition/reload contract and fails closed when unsupported. `AnalogCombatCompatibility` validates installed CE signatures and IL callsites before applying controlled-pawn coordinate, bounds, and velocity hooks. Targeted transpilers augment projectile cell candidate queries and recenter target calculations, preserving CE's narrowphase collision and damage logic. Unsupported analog contracts select native path fallback. There are no damage writes or projectile replacements.

`NativeScene` creates original low-polygon meshes from nearby map state. Static geometry is cached in 12 × 12 chunks; a radius of three chunks bounds the cache to 49. Missing chunks are built nearest first, at most one per frame. Once warm, one chunk is checked per 100 ms and rebuilt only after its content signature changes. Map-mesh dirty notifications prioritize affected chunks; the 100 ms round-robin scan is a fallback. The camera far plane is 30 cells to keep its view inside the cached neighborhood. Static geometry is batched; live pawns and door leaves reuse prototype meshes. Palette colors and per-face shading use the game's depth-writing Cutout shader.

Both targets share source, with a separate build for 1.6 (.NET Framework/Unity references) and 1.7 (.NET 10/Waylith Unity-compatibility references). Read-only inspection verified the 1.7 mesh, camera, input, and draw APIs are implemented. No decompiled engine code is included in the project.

`NativeWeapons` builds and caches twelve model families, assembled and split into body/feed/bolt parts, with hands, world/dropped weapon poses, and observed-shot recoil. `NativeReloadAnimation` reads the actual CE reload job, current delay toil, remaining ticks, and ammo changes. It drives magazine, cylinder, shell, bolt, and hand poses without changing the job or ammo. Single-round loading holds the weapon open between real toils; unknown timing gets a lowered pose. `NativeCombatEffects` observes real launch, impact, deflection, and CE beam events. It maintains bounded projectile/trail/spark state and never writes damage, ammo, trajectory, or simulation RNG. Cosmetic reflected sparks are separate from real projectile ricochets.

`NativePawnModels` captures value-only appearance snapshots from body type, colors, worn apparel layers/coverage and recognized missing/prosthetic structural limbs. Nine family rigs and six human shapes provide generic coverage; classification is deliberately heuristic for unfamiliar mods. A stable appearance hash drives invalidation. `NativePawns` caches at most 64 appearances plus nine shared fallback families. It checks at most two appearances and builds at most one articulated rig each frame. Up to 16 nearby pawns within 14 cells use separate body/head/limb/tail meshes; other pawns retain assembled models. Disabling **Animate nearby pawns** keeps the dressed assembled models.

`NativePawnAnimation` derives presentation from actual motion, jobs, posture, observed attacks and positive damage. Its bounded 256-pawn observation cache advances phase on simulation ticks and clears with the scene. Gait, aim, recoil, melee, reload, work, eating/carrying and injury poses do not modify combat timing or damage. First-person weapon/hands reuse the controlled pawn's appearance and action state. `NativeObjectModels` adds 32 procedural object families before the existing size-aware fallback. The model catalogs are depth-buffered CPU projections of the same compiled geometry, without a live engine renderer.

Version 0.5.1 shares the drawn arm transform with third-person weapon sockets, retaining static sockets when articulation is disabled or over budget. Draft state chooses held or stowed equipment; CE handedness metadata overrides fallback classification. `NativePawnEquipment` reads owned physical shields and reuses bounded colored meshes for hand/back placement and first-person drawing. Energy belts are excluded from board models. Native bed head/foot slots determine sleeping position and orientation. Actual door classes bypass static family meshes, and resource-piece thresholds participate in chunk signatures.

Version 0.5.2 separates ranged aim orientation from the arm socket rotation while retaining the attached grip. Available-hand allocation is shared by held weapons, physical shields and first-person placement. Lying-target selection transforms the aim ray into the same local bounds and root transform used to render the body, including bed elevation and rotation.

`NativeShieldEffects` reads active `CompShield` state for faint native-view haze and observes successful shield absorption/parry outcomes for blue/red echoes. Its effect pool and transparent meshes have a separate lifecycle from `NativeScene`, allowing the opt-in colony-view effects to continue after first-person exit. Map/game changes clear observations; each native-view takeover invalidates nearby haze candidates while preserving impact events. Native damage handlers remain authoritative; presentation patches do not change damage, armor or shield energy.

Version 0.5.3 adds `NativeBloodEffects`: positive post-armor pawn damage and native bleeding callbacks produce short-lived, tick-driven particles in a reusable mesh. Gore consists of cosmetic tissue fragments; it does not remove anatomy or alter injuries. Persistent trails come from existing native blood filth baked into the local scenery cache, so native cleaning, rain and save data remain authoritative. Projectile contact effects classify the hit surface for sparks, debris or splashes; pawn contact alone never proves a bleeding injury. Blood and projectile effects are bounded and released with the native scene.

`NativeLighting` samples the game glow grid, sky, and roofs, with bounded temporary flashes. Static meshes are relit incrementally; face-center samples avoid neighboring-cell light leaking across walls. Changing color buffers may cause a full Waylith mesh upload, so only one cached chunk is relit per frame. `NativeWeather` updates a single bounded precipitation mesh at 20 Hz using actual weather rates and game ticks. It suppresses covered/fogged cells and draws simple depth-occluded sun/moon cues from local time. Snow accumulation and roofs remain simulation-owned.

The old `Client/`, `BridgeServer`, and wire serializer are retained for historical regression tests and the reproducible transport-cost benchmark. They are not the active view or input path, and the native installable package excludes browser assets. `protocol.md` describes that retired transport only.

Known limitations: generic object shapes and terrain colors, bounded view distance, delayed static-geometry updates, no bespoke model coverage for every modded object, no multiplayer, and no runtime certification from compilation alone. See the smoke matrix before calling a release compatible.

Version 0.5.4 adds scoped shot metadata for stock straight vanilla bullets. Exact crosshair endpoints replace cell-centre quantisation while preserving native miss offsets and hit eligibility. Height-aware collision filtering rejects out-of-ray contacts; empty-air expiry does not create a ground impact. Arcing, explosive and custom vanilla projectile classes retain their native trajectory. Owned projectile metadata is saved with the projectile and outlives the view, without retaining pawn or map references. CE continues to use its native projectile trajectory and collision handlers.



Version 0.5.5 rebases CE's cached distance estimate to the current crosshair range while retaining its sampled relative error. Guards reject invalid owned casts before native ammunition preparation. Stock vanilla shots preserve successful native Thing hits without cosmetic endpoint jitter, retain world collision eligibility and keep both travel counters synchronized. Final target checks use the last actual movement segment, scoped with exception-safe cleanup. Game changes clear CPU targeting caches even if in-flight shots repopulated them after first-person exit.
