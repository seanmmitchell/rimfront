## Combat Extended boundary

The adapter expects `CombatExtended.CompAmmoUser` with `TryStartReload()`, `CurMagCount`, `MagSize`, `HasMagazine`, `HasAmmo`, `UseAmmo`, and `CanBeFiredNow`. These signatures were found in the installed CE assembly. An unsupported contract disables controlled firing/reloading with a status message. Native weapon verbs and reload jobs remain authoritative.

Analog movement additionally needs verified CE coordinate, collision-query, bounds, and lead contracts. It uses isolated controlled-pawn patches and targeted query transpilers; unsupported contracts select native path fallback. Mod settings can select that fallback explicitly. Oversized body bounds also fall back instead of shrinking the collision footprint. Tight corners use a conservative square footprint, and analog travel is capped at 0.25 cells per tick. Compatibility with other pathing and combat patches requires a live test of the exact mod list.

Reload presentation reads the actual CE `ReloadWeapon` job, current delay toil and remaining ticks, and magazine observations. Unsupported timing falls back to a lowered weapon pose; it never fabricates ammo or finishes a job. Native reload behavior and animation appearance still require separate runtime checks.

The Windows icon safeguard captures/restores the game window's existing icons around view transitions. It has not been validated against the user's live taskbar regression, and no confirmed root cause is claimed. Follow the taskbar entry/exit and focus-loss smoke case after installing the updated DLLs.

The icon tests execute its real lifecycle guard with a fake backend and clock, covering unchanged/changed/missing icons, bounded ownership, replacement windows, foreign ownership and a read/write ownership race, partial allocation cleanup, and bounded retries. They call no Windows native window APIs and do not inspect or modify live UI.

The inspected upstream CE source revision `979aed6f0dfe8d73775f0ef687445c6350bb120b` advertises 1.6. That source inspection does not establish a supported 1.7 release. Use an appropriate CE version for each game branch and validate the exact installed configuration.

Native view suppresses stock flat dynamic/map drawing while active. Version 0.3 adds observed vanilla/CE projectile trails, CE beam segments, and impact/deflection fragments; arbitrary stock/mod motes and unsupported custom visual effects remain outside this renderer. Underlying trajectories, damage, timing, and sounds remain owned by the simulation. Custom visual mods need separate evaluation.

## Model and animation coverage

Version 0.5 uses nine generic rig families, six human body shapes, fourteen apparel families, twelve weapon families, and 32 additional object families. It does not supply bespoke models for every game or mod definition. Appearance captures actual colors and recognizable clothing/anatomy data; unfamiliar anatomy, special apparel, xenotype features and custom graphics can remain approximate. The seven-part rig cannot represent every multi-limbed anatomy independently.

The [pawn/apparel](model-catalog.png), [outfit/action](action-catalog.png), and [object](object-catalog.png) catalogs use actual compiled Builder buffers and pose helpers, rendered offline with a CPU depth buffer. Geometry tests cover finite/nondegenerate bounded meshes, family envelopes, rig rest-pivot reconstruction, combined clothing, and floor/bed clearance across body scales. Appearance tests cover classifier priorities, unknown-definition fallback, cache-key changes, missing limbs and apparel variants. Animation tests cover tick-based pause/phase behavior, finite poses, mirrored gait, recoil/injury expiry and action priorities. Runtime appearance capture, mesh-cache disposal, shader behavior and animation quality still require live checks.
